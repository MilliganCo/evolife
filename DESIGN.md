# Дизайн Evolife

## Обзор архитектуры

Evolife реализует эволюционную симуляцию клеточного автомата "Игра Жизнь" с генетической системой. Основная идея - позволить клеткам эволюционировать и наследовать правила поведения, создавая сложные экосистемы с адаптивными стратегиями.

## Ключевые решения

### 1. Генетическая система

#### Геном клетки
```python
@dataclass
class Genome:
    birth_mask: int      # 9 бит - условия рождения
    survive_mask: int    # 9 бит - условия выживания
    mut_bits: int        # 8 бит - частота мутаций
    glyph_id: int        # 0..K-1 - ASCII символ
    color_id: int        # 0..15 - ANSI цвет
    age_max: int         # 1..255 - максимальный возраст
```

**Обоснование:**
- **Маски правил**: Прямое кодирование правил Conway's Life в битовых масках
- **Частота мутаций**: Эволюционирующий параметр, позволяющий видам адаптировать скорость изменений
- **Визуальные признаки**: Глифы и цвета для различения видов
- **Старение**: Механизм селективного давления

#### Наследование и мутации

**Кроссовер:**
- Однородный кроссовер для масок (50/50)
- Случайный выбор родителя для скалярных генов
- Среднее арифметическое для частоты мутаций

**Мутации:**
- Инверсия случайного бита в масках
- Сдвиг ±1 для частоты мутаций
- Соседние значения для глифов и цветов
- Сдвиг ±5 для максимального возраста

**Обоснование:**
- Однородный кроссовер сохраняет разнообразие в масках
- Ограничение мутаций предотвращает деградацию генома
- Соседние мутации сохраняют функциональность

### 2. Система видов

#### Кластеризация по Хэммингу
```python
def get_species_id(self, birth_mask: int, survive_mask: int) -> int:
    for (existing_birth, existing_survive), species_id in self.species_map.items():
        if (self._hamming_distance(birth_mask, existing_birth) <= self.hamming_threshold and
            self._hamming_distance(survive_mask, existing_survive) <= self.hamming_threshold):
            return species_id
```

**Обоснование:**
- Группирует похожие правила в виды
- Настраиваемый порог для контроля детализации
- Эффективный поиск по хэш-таблице

### 3. Производительность

#### Векторизация с NumPy
```python
def _count_neighbors(self) -> np.ndarray:
    counts = np.zeros((self.height, self.width), dtype=int)
    for dy in [-1, 0, 1]:
        for dx in [-1, 0, 1]:
            if dx == 0 and dy == 0:
                continue
            shifted = np.roll(np.roll(self.cells, dy, axis=0), dx, axis=1)
            counts += shifted.astype(int)
    return counts
```

**Обоснование:**
- `np.roll` для тороидальной топологии
- Избегаем `scipy.ndimage` для минимальных зависимостей
- Векторизованные операции NumPy

#### Двойная буферизация
```python
def _build_frame(self, cells, genomes, ages, stats):
    self.buffer_lines[0] = "┌" + "─" * self.width + "┐"
    for y in range(self.height):
        line = "│"
        for x in range(self.width):
            char = self._get_cell_char(x, y, cells, genomes, ages)
            line += char
        line += "│"
        self.buffer_lines[y + 1] = line
```

**Обоснование:**
- Предварительное построение строк
- Минимизация системных вызовов
- Быстрое обновление экрана

### 4. Модульная архитектура

#### Разделение ответственности
- **engine.py**: Логика симуляции, правила, обновление
- **genetics.py**: Геномы, мутации, кроссовер, виды
- **render.py**: ASCII визуализация, режимы отображения
- **io.py**: Сохранение/загрузка, импорт паттернов
- **metrics.py**: Статистика, анализ, отчеты
- **config.py**: Конфигурация, валидация
- **cli.py**: Интерфейс, управление, цикл симуляции

**Обоснование:**
- Четкое разделение функций
- Легкое тестирование
- Возможность независимого развития модулей
